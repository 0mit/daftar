Your machines, and the domain they answer on

Sam keeps a NAS at home that serves his website, has registered example.org for it, and rents a virtual server. Each of these is one bean: what it is, what identifies it, who said so, who owns it and who answers for it. The domain's registration runs out on a date, and a tool reads that date before it does.

garden-sam · daftar v0.34.0 · the day held at 2026-10-27

What the notebook records

A domain is registered for a term, not owned outright: the registry is its external owner, and Sam answers for it. Its registration belongs to the domain profile, which the garden opts into in its own VOCAB.md — a change to the garden's law, journalled as a RULE-CHANGE:

extends_profiles: [domain]
beans/example-org.md---
bean: example-org
genos: domain
title: "example.org — Sam's domain"
status: active
summary: "The domain Sam's website answers on."
nature: lekton
identity:
  status: confirmed
  anchors:
    - { key: fqdn, value: "example.org", class: logical, establishing: true }
provenance: { src: observed, by: "sam", as_of: 2026-09-17 }
owned_by: { legal: { external: "the .org registry, under a registration agreement" } }
responsibility: { legal: { holder: { bean: sam } } }
registration:
  registrar: "Example Registrar Inc."
  created: 2020-01-15
  expires: 2027-01-15
  auto_renew: enabled
  observed: 2026-09-17
  source: "WHOIS for example.org, read 2026-09-17"
---
Sam's domain.

The NAS is a host, of the nature soma — a body — identified by the serial on its sticker; its host name only corroborates. provides_habitat is what lets a running thing live on it:

  - { role: web }

The NAS.

The website is an instance: a running copy of nginx that lives on the NAS and is Sam's. “Serves this domain” has no relation of its own, so it is a refs entry with a rel:

beans/website.md---
bean: website
genos: instance
title: "website — nginx on the NAS, serving example.org"
status: active
summary: "The web server instance on the NAS that answers for example.org."
nature: empsychon
identity:
  status: confirmed
  anchors:
    - { key: service_id, value: "nginx:example.org@nas", class: logical, establishing: true }
provenance: { src: observed, by: "sam", as_of: 2026-09-17 }
instance_of: { bean: nginx }
lives_in: { bean: nas }
owned_by: { legal: { owner: { bean: sam } } }
responsibility: { legal: { holder: { bean: sam } } }
refs:
  domain: { bean: example-org, rel: serves }
---

The software it runs, and the rented server

nginx is a product owned by its project. The rented server is a virtual-host: it has no matter of its own, so it is identified by its name, and the provider owns it.

Before an agent touches the website, dmcursor says what it is and where it lives, and what must be attended to first:

~/garden-sam$ python3 bin/dmcursor.py website
cursor -> website   instance · empsychon · living in nas
  website — nginx on the NAS, serving example.org

MEASURED  — what is already known, and whether it still holds
  cache  none — this being has no recorded analysis; reading is unavoidable

  none recorded on this being

INHERITED — along every chain the vocabulary declares acyclic
  nothing constraining inherited from any chain

dmstale reads the registration's expiry date and warns inside 90 days. It exits 1 when something needs action:

~/garden-sam$ python3 bin/dmstale.py
EXPIRING example-org.registration  expires 2027-01-15 (80 days)  auto_renew=enabled  registrar=Example Registrar Inc.  <-- an unrenewed name takes its DNS and its mail with it

expiring: 0 ok, 1 within their horizon, 0 EXPIRED

analysis_cache: 0 fresh, 0 stale, 0 not on this host, 0 unknown
exit 1

The gate's last line names the garden, the release it runs, its gardener and its id:

~/garden-sam$ python3 bin/dmcheck.py --all
garden-sam (daftar v0.34.0, gardener sam, garden 8d48e6b4669f): 6 docs, 0 error(s), 0 warning(s)

What it shows

  • Identity is by anchor, not by file name. A serial for the NAS, a domain name for the domain and for the rented server: two notebooks that never met recognise the same thing by it.
  • Ownership and habitat are separate. The website is Sam's, and lives in the NAS; moving it to another machine changes where it lives, never who owns it. Ownership rises.
  • A date that runs out is read by a tool, not by the gate. A check whose result changed with the calendar would make the gate refuse on some day for no committed reason; dmstale says so in its header.
