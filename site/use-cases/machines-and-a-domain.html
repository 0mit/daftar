Your machines, and the domain they answer on

Sam keeps a NAS at home that serves his website, has registered example.org for it, and rents a virtual server. Each of these is one bean: what it is, what identifies it, who said so, who owns it and who answers for it. The domain's registration runs out on a date, and a tool reads that date before it does.

What Sam says, and what he reads

Orient — for the person. Sam tells his agent what he runs, and asks to be warned in time. The conversation is written for this page; everything the agent reports in it is what the tools print under Operate.

  1. Sam · typed

    My website runs on the NAS at home, on example.org. I also rent a small server somewhere. Keep track of all of it, and tell me before the domain runs out.

  2. Sam's agent

    Which web server runs the site on the NAS? And who is the domain registered with — do you know when it expires, and whether it renews itself?

  3. Sam

    nginx. Example Registrar; it runs to the middle of January, and auto-renew is on.

  4. Sam's agent

    Five pages, one for each thing: the domain, the NAS, the website that lives on it, nginx — software owned by its own project, not by you — and the rented server. Each says who owns it, who answers for it, and that you are the one who said so. The notebook's check passed each time.

    One warning already: example.org's registration expires on 15 January 2027 — in 80 days. Auto-renew is on, so this is a reminder, not an alarm; I will say it again whenever you ask what needs attention.

  5. Sam

    If I ever move the site off the NAS, what breaks?

  6. Sam's agent

    Before touching the website I look it up first: it lives in the NAS, and nothing is recorded that must be attended to before it is touched. The NAS is where I would start.

What the notebook records

Inspect — for the auditor. Exactly what was written, and why it is shaped so.

Every bean says what sort of being it records, in two words the law takes from Greek. Its nature is one of three: soma, a body — a being with extension in space, as the NAS is; lekton, the sayable — a being that exists by being said and agreed, as a domain is, or a program's code; or empsychon, the ensouled — a being that strives to persist as itself while it is alive: a person, or a program while it runs. Its genos, a kind, refines the nature: host, domain, instance. Each word, with its Greek.

A domain is registered for a term, not owned outright: the registry is its external owner, and Sam answers for it. Its registration belongs to the domain profile, which the garden opts into in its own VOCAB.md — a change to the garden's law, journalled as a RULE-CHANGE:

extends_profiles: [domain]
beans/example-org.md---
bean: example-org
genos: domain
title: "example.org — Sam's domain"
status: active
summary: "The domain Sam's website answers on."
nature: lekton
identity:
  status: confirmed
  anchors:
    - { key: fqdn, value: "example.org", class: logical, establishing: true }
provenance: { src: observed, by: "sam", as_of: 2026-09-17 }
owned_by: { legal: { external: "the .org registry, under a registration agreement" } }
responsibility: { legal: { holder: { bean: sam } } }
registration:
  registrar: "Example Registrar Inc."
  created: 2020-01-15
  expires: 2027-01-15
  auto_renew: enabled
  observed: 2026-09-17
  source: "WHOIS for example.org, read 2026-09-17"
---

The NAS.

The website is an instance: a running copy of nginx that lives on the NAS and is Sam's — of the nature empsychon, because it exists while it runs. “Serves this domain” has no relation of its own, so it is a refs entry with a rel:

bean: website
genos: instance
title: "website — nginx on the NAS, serving example.org"
status: active
summary: "The web server instance on the NAS that answers for example.org."

  status: confirmed
  anchors:

provenance: { src: observed, by: "sam", as_of: 2026-09-17 }
instance_of: { bean: nginx }
lives_in: { bean: nas }
owned_by: { legal: { owner: { bean: sam } } }
responsibility: { legal: { holder: { bean: sam } } }
refs:
  domain: { bean: example-org, rel: serves }
---

The software it runs, and the rented server

nginx is a product owned by its project. The rented server is a virtual-host: it has no matter of its own, so it is identified by its name, and the provider owns it. It is empsychon too, not soma: it has no body, exists while it runs, and ends when it is torn down.

What it shows

  • Identity is by anchor, not by file name. A serial for the NAS, a domain name for the domain and for the rented server: two notebooks that never met recognise the same thing by it.
  • Ownership and habitat are separate. The website is Sam's, and lives in the NAS; moving it to another machine changes where it lives, never who owns it. Ownership rises.
  • A date that runs out is read by a tool, not by the gate. A check whose result changed with the calendar would make the gate refuse on some day for no committed reason; dmstale says so in its header.
